How the measurements were made
  • All coordinates are in the coordinate system of the phone screen (390 × 844 CSS pixels, origin at the top-left corner of the white screen). The phone is never resized during the experiment.
  • The red START button is not a trial. Clicking it only sets the origin for trial 1, so every recorded trial has a real previous target and no trial had to be excluded.
  • A is the distance between the center of the previous target and the center of the current target, calculated from the rendered target rectangles. The CSV holds this measured value, plus the requested value in RequestedA.
  • Targets are full-width horizontal bars, so the only movement direction is vertical. W is the bar's height (the only dimension that moves); its width always spans the screen's safe area.
  • MT runs from the previous successful selection to the current successful selection, measured with performance.now(). Targets are selected on mouse press.
  • Clicks outside the target never end a trial. They are counted in Misses, and their time stays inside MT. Presses within 150 ms of a successful selection are ignored so a double-click cannot register.
  • Each target lies fully inside the safe area of the screen, kept away from the top and bottom edges of the screen. If a requested A could not fit, the closest valid position is used and the measured A is recorded. Compare A with RequestedA in the CSV to check that this never happened.
  • Order: 3 blocks, each containing all 25 combinations of A and W in random order. The order is generated from the seed shown in the Seed column, so it can be repeated.
